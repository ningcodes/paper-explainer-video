## s1_manim
# 风格 1 · 数学动画（3Blue1Brown / Manim 风）

**这是什么**：模仿 3Blue1Brown（Grant Sanderson）用 Manim 做的数学动画。深灰画布上铺一层极淡的 NumberPlane 网格，所有对象都像是被一笔笔「写」出来的：文字先描轮廓再填色（Write），图形沿路径画出（Create），物体之间靠移动、缩放、变形接续（Transform），全片 13.6 秒是一个连续镜头，没有硬切，镜头只做 3% 的缓慢推近。整体是「数学讲义」的感觉：模型是一个 4×4 权重矩阵加一把描线锁（`Δ𝜃 = 0`），Harness 是一个围住它的圆，上面用 LaggedStart 依次点亮 6 个组件；三张表画成三个列向量 `[排期] [人员] [预算]`，逐行框选对账，红色的 1.8 被替换成 3.0 并打勾；分数是一根 0–100 的数轴，加一个滚轮式 DecimalNumber 从 43 滚到 78，最后用 Brace（花括号）标注「只改 Harness」。

**参考**：3Blue1Brown YouTube 频道（Essence of Linear Algebra、Neural Networks 系列），Manim Community 的默认视觉语言。

**关键参数**
- 色板：背景 #1C1C1C（加径向暗角）；BLUE #58C4DD（模型 / model）、TEAL #5CD0B3（Harness 环与公式）、YELLOW #F4D345（强调：锁的 Indicate、对账框、78、进度条当前节）、GREEN #83C167（预算、✓、修正值）、GOLD #F0AC5F（人员）、RED #FC6255（对不上的数）、GREY #888888（注释）、正文 #ECECEC
- 字体：拉丁字母和数字用 Latin Modern Roman（数学变量用斜体：*agent*、*model*、*Harness*、*JobBench*、*d*₁），希腊字母用 Latin Modern Math（Δ、𝜃）；中文用 Noto Serif CJK SC（SemiBold 做标题，Regular 做注释）
- 动效：缓动统一用 Manim 的 `smooth`（sigmoid 型），Write 先描边后填色、逐字错峰；Create 用 stroke-dashoffset；Indicate 做 1.2 倍放大加变黄再还原（锁、表名、Harness、78、Harness 环）；LaggedStart 错峰 0.07–0.2 秒
- 转场：不切屏。Harness² 大标题缩小后飞进左上角的来源标签；Δ𝜃 = 0 上移淡出，*agent = model* 在原位写出；整个 Harness 图缩到 0.6 倍移到左边，给右边腾地方；表格上移淡出时，数轴在原位画出
- 进度条：深色条，Latin Modern 编号加宋体节名，细灰线，当前节编号和已播进度用 YELLOW
- 字幕：Noto Serif CJK SemiBold 44px，#ECECEC，半透明黑底，没有边框（类似 3b1b 的字幕）

**适合**：讲机制、公式、结构的段落（论文核心思路、拆解架构、数字对比），观众会觉得「严谨、有数学感」，和论文解读频道的定位很契合。

**缺点**：调性偏冷、偏学术，钩子的情绪冲击力不如高饱和的风格；画面信息密度高，手机小屏上权重矩阵里的小数字只能当纹理看；中文宋体和 LaTeX 字体混排时，中英间距需要逐处手调；字形变形（真正的 glyph morph）没有实现，Transform 是用位移、缩放加交叉淡化近似出来的。

## s2_sketch
# 风格 S2 · 手绘白板 / Excalidraw 草图风

**一句话**：整段钩子画在一张持续存在的无限白板上：镜头像在 Excalidraw 里平移、缩放，一支小铅笔跟着笔画走，把论文卡片、模型、Harness 环、三张表、温度计分数逐一画出来，画过的内容都留在板上，最后拉远成一张完整的手绘海报：“不动模型，只改 Harness”。

**参考**：Excalidraw / rough.js 的手绘图形语言；ByteByteGo 式系统设计图，只是改成手绘；YouTube 上的白板 / sketchnote 讲解视频（如 Fireship、Hussein Nasser 等的手绘图段落，以及 RSA Animate 的白板叙事）；小红书、B 站“手绘知识卡片”类账号。

## 关键参数
- **画布**：暖白纸 `#FDFCF8`，`#E7E3DA` 点阵（32px，跟随镜头移动，所以能看出是一张很大的板），叠一层固定的纸张噪点（multiply）和很轻的暗角。
- **线条**：自写的种子化 rough 生成器。每条线都是两遍略有偏差的三次贝塞尔，端点抖动约 1.5px，中段有弯曲（bowing）。椭圆有起笔重叠（overshoot），双圈。墨色 `#1E1E1E`，3–4px，圆头。
- **填充**：Excalidraw 色板做软马克笔色块，前沿是斜边擦出：黄 `#FFEC99`、蓝 `#A5D8FF`、绿 `#B2F2BB`、粉 `#FFC9C9`、紫 `#D0BFFF`。温度计用 45° hachure 排线（灰→绿）。强调用红马克笔 `#E03131`：下划线、划掉 43、圈出“对上账”，78 本身也是红色。
- **字体**：中文用霞鹜文楷（标题和字幕 Bold，说明 Regular），英文和数字用 Caveat Bold（Harness、43、78、刻度、进度条编号）。最小可读字 28px，字幕 46px。
- **动效语法**：
  - 笔画 draw-on：每段子路径按长度分配时间，用 pen 缓动，0.2–0.5s；
  - 文字按书写方向斜边擦出，铅笔跟着走并轻微上下抖动；
  - 便利贴和 Harness 标签“啪”地贴上去：起始放大 1.45–1.6 倍，用 back 缓动回弹，同时旋转回正，6 个标签每个错开 130ms；
  - 镜头只用 inOutCubic 平移和缩放（缩放走对数插值），没有任何淡入淡出转场。段落顺序：论文卡 → 模型 → Harness 环（右移）→ 任务区 → 下移到打分区 → 拉远成全景海报。
- **进度条**：顶部一把手绘尺：一条双遍墨线，带小刻度，8 节按时长比例分段。编号用 Caveat，节名用文楷。当前节“01 钩子”盖一道黄色马克笔，红色马克笔线和红点做播放头，随 t 前进。
- **字幕**：白色撕纸条（锯齿上下边，带软阴影），文楷 Bold 46px。关键词用黄色荧光笔底（都没动 / 真实 / 对上账），Harness 和 78 用红色 Caveat。字幕带 back 缓动的上弹入场，左右交替轻微倾斜。
- **头像**：做成贴在白板上的拍立得：白底、手绘描边，上面贴一条黄胶带。

## 适合什么内容
系统设计、Agent 架构、流程和对账这类“结构图讲解”。也适合论文机制拆解，因为画面可以一直累积，最后一张全景图就是这一段的总结卡，截图就能当封面或笔记。风格亲和、有“老师在白板上给你讲”的感觉，和霞鹜文楷的小红书调性契合。

## 缺点
- 信息密度上限低：全景海报里小字（标签、副标题）缩到 0.52 倍后大约只有 14–16px，只能当氛围看。
- 手绘风在“震撼感”上弱于粗黑展示体或暗色科技风。43→78 是靠画出来、圈出来强调的，没有数字滚动的冲击力。
- 铅笔光标在几个并行笔画之间会跳（总是跟最新开始的那一笔）。
- 长视频全程用这一套，容易显得单调，需要配合照片、论文截图等真实素材穿插。

## s3_brutal
# S3 · 新粗野主义 / 贴纸潮流风（Neo-brutalism Sticker）

**一句话**：大块纯色 + 5px 黑描边 + 无模糊硬投影的「贴纸」卡片，所有元素从画外砸进来、落地挤压回弹，强调点用「盖章」和「投影按压」，像创作者经济品牌（Gumroad / Figma 社区 neubrutalism 模板 / daisyUI neubrutalism token）的发布视频，配上 zine 胶带和半调网点的街头感。高对比、好玩但有自信，很适合小红书信息流里第一秒抓眼。

**参考**：Gumroad 2021 后的品牌改版、Figma Community 的 Neubrutalism UI Kit、daisyUI「neubrutalism」主题色、Hey/Poolsuite 式创作者解说视频、独立杂志 zine 的胶带与贴纸拼贴。

## 关键参数
- **色板**：底 `#FBFBF9` / 奶油 `#FFF4D6`；墨/描边 `#111111`；主黄 `#FDC800`；紫 `#432DD7`；热粉 `#FF5C93`；薄荷 `#23D18B`；天蓝 `#5BC0FF`。纯平色，无渐变。每个段落换一整屏底色（奶油 → 网格白 → 天蓝 → 紫），用硬切/推刷转场。
- **形状**：卡片 5px 黑描边、圆角 12–16px、硬投影 `8px 8px 0 #111`（大件 12–14px）；贴纸旋转 −6°…+6°；装饰用半调圆点（28px 网格）、60px 方格纸、滚动胶带。
- **字体**：中文标题 Noto Sans CJK SC 900；英文/数字 Archivo Black（43/78、HARNESS、JobBench）；标签 Space Grotesk 700；小元信息 JetBrains Mono 700。
- **动效规则**：阻尼弹簧（w≈18–24, z≈8–12，带过冲）；卡片从上方重力下落 0.17s 后挤压回弹（scaleX/Y ±13–16%）；贴纸沿单轴从画外甩入；强调时投影「按下」（偏移 8→0→8，0.22s）；印章效果：2.4–2.8 倍缩放 0.1s 砸下 + 小幅回弹 + 屏幕震动（仅 78）；胶带匀速滚动。错峰 0.1s。
- **转场**：0→1 段是标签「飞成角标」（同一元素连续变形）；1→2（Harness → 职场任务）是从右推入的黑边色块刷屏；2→3（对账 → 打分）是从下往上的色块刷屏。没有整屏淡入淡出。
- **固定元素**：顶部进度条 = 奶油底黑边条 + 8 个胶囊，当前节「01 钩子」加宽、黄色填充随播放推进，右端黑底黄字时间码；字幕 = 黑色胶囊白字 46px + 黄色硬投影，关键词标黄；头像下垫天蓝描边底座 + 「刘铁柱 · ning.codes」小标签。

## 适合
产品发布、工具/论文「一个反直觉结论」类钩子、数字对比、清单类内容；年轻、科技 + 潮流受众。对数字和标签型信息（43→78、6 个组件）表现力最强。

## 缺点
- 视觉噪音高：信息密度一大就显得乱，不适合长段公式推导或需要静下来读的内容；5–6 分钟全片用同一套会疲劳，需要在中段降饱和。
- 风格辨识度来自「贴纸感」，容易被认为偏营销/偏可爱，削弱「论文解读」的严肃感。
- 进度条非当前节的名字只有 18px，手机上偏小（信息仍可辨认，但不算「可读字」）。

## s4_editorial
# 风格 4 · 报刊数据新闻（FT / Bloomberg / NYT Graphics 风）

**是什么**：把 13.6 秒的钩子做成一版“报纸头版 + 数据图表”。三块版面（论点 → 案例 → 结果）像翻页一样横向滑过，每块都是“栏目标签 + 大标题 + 导语 + 图”的头版结构，最后定格在一张 FT 风格的斜率图上：43（牛津蓝）→ 78（FT 酒红），旁边标注「+35 分」，并加一条冷静的小字注释「单个案例 · 平均提升没这么大」。气质是权威、克制、以数据为先：不弹跳、不发光，靠字体层级和细线把信息排清楚。

**参考**：Financial Times Visual & Data Journalism（FT 三文鱼粉底、claret 强调色、细线网格），Bloomberg QuickTake / Businessweek 动态图表，NYT The Upshot 动画图表，The Economist 视频里的图表段落。

**关键参数**
- 色板：纸 #FFF1E5｜墨 #33302E｜次要 #66605C｜细线 #CCC1B7｜FT 酒红 #990F3D（关键数字 78、Harness 外框、栏目短线）｜牛津蓝 #0F5499（基线 43、冻结锁）｜青 #0D7680（对账连线、打勾）｜麦色面板 #F2DFCE
- 字体：中文标题 Noto Serif CJK SC Black（132 / 92 / 84px，行距约 1.1）；正文和标签用 Noto Sans CJK SC；数字用 Inter 800 等宽数字（tnum）；栏目标签用 Inter/思源黑 Bold 28px、字距 0.14em，上面压一条 56×5 的酒红短线；左下角固定一行灰色来源。
- 版式：左边距 120px 起排，左栏放标题和导语，右栏放图解；靠 1px 细线和 4px 粗线分层；图表只画横向网格线，标签直接贴在线和点上，不用图例；注释用细引线 + 短说明。
- 动效：标题逐行遮罩上推（easeOutQuart，0.55–0.6s）；导语从左往右擦出；细线从左往右长出；Harness 外框顺时针描边（easeInOutCubic 1.25s），描到哪个部件，哪个部件的标签就弹出来；权重格子从左往右“冻结”变成灰蓝；表格逐行上浮，每行错开 80ms；对账连线依次画出，再打勾；斜率线从 43 画到 78，旁边数字跟着滚动；图表镜头缓慢推近 3.5%；关键短语用酒红荧光笔和下划线扫出来。
- 转场：版面像翻报纸一样整页横滑（0.62s easeInOutCubic），配 paper + 轻 whoosh 音效。
- 固定元素：顶部是报纸栏目导航（「论文速读」报头 + 01–08 栏目，当前一节用酒红宋体并加下划线，下划线长度显示本节进度，底边酒红细线显示全片进度，右侧是等宽时间码）；字幕放在麦色电视下三分之一条里，上面压一条细线，用宋体 Bold 44px；头像直接放在纸面上，不加框。

**适合什么内容**：有硬数字、前后对比、“反直觉的结论 + 需要打折扣的注释”的段落，比如结果、冷水和消融实验。也适合需要显得可信、严肃的论文解读。

**缺点**：克制到偏冷，刷小红书时的抓眼程度比不上高饱和或手绘风；前 1.3 秒左栏只有报头和来源，视觉冲击靠右侧的权重格子撑着；三张表的内容是示意（场次/班组/科目），没有用论文里的原始表格；字多、层级多，手机竖着看时 28px 的注释仍然偏小；整体太像“新闻”，和刘铁柱轻松的人设会有点反差。

## s5_terminal
# S5 · 暗色开发者 / 终端 + 产品发布会风

**一句话**：把论文讲成一次"开发者产品发布"——终端敲命令推进叙事，代码、文件、测试输出本身就是画面主体；暗底、发丝描边、霓虹光晕，节奏是 Fireship 式的快推近 + 硬切，质感对标 Vercel / Linear / Raycast 的发布视频。

**参考**：Fireship（"in 100 seconds" 系列的代码居中、快速推近、硬切）；Vercel Ship / Linear Release / Raycast 发布片（暗色、1px 发丝边框、层叠 box-shadow 光晕、克制的渐变）；IDE 标签栏 + test runner 输出的界面语言。

**色板**：底 `#0A0A0B` + 48px 网格 `#16161A` + 跟随场景焦点移动的径向光（青→绿→琥珀→绿）；面板 `#111114`、描边 `#26262C`、圆角 12px；正文 `#EDEDED`、次要 `#8A8A93`；强调：霓虹绿 `#3DF5A6`（成功 / 78 / Harness 环）、青 `#4CC9F0`（冻结 / 信息 / 扫描线）、琥珀 `#FFB547`（警告 / 43 / 冲突格）、品红 `#FF4FD8`（只用在 `False` 一处）。

**字体**：JetBrains Mono 400/500/700（命令、文件名、数字、标签、大分数 400px）；Inter Display Bold 字距 -0.045em（Google / Harness 大标题）；Noto Sans CJK SC Medium/Bold（中文标题、字幕）。

**镜头结构（13.6s）**：
1. `~/papers ❯ cat paper.txt` 逐字敲出 → 输出 title/from → 「Google 新论文」弹出 + 发光下划线 + 推近。
2. 硬切（2 帧闪白 + 青/品红横向切片）→ `weights.safetensors` 面板里 16×9 权重格对角错峰弹入；右侧 `git diff --stat` 输出 `0 files changed`，大字卡 **0 lines changed**；念到"没动"时锁弹出、权重褪成冷灰、`requires_grad = False` 敲出，推近到锁。
3. 连续变形：模型面板缩到中央，`harness/` 文件夹边框沿周长描出，6 个文件卡（提示词 / 护栏 / 技能 / 工具说明 / 脚本 / 记忆）从两侧滑入、LED 点亮、连线上跑光点；念到 Harness 时大字逐字母弹出 + 绿色光晕 + 推近。
4. 硬切 → `harness run --task jobbench/producer-reconcile` + 转圈 spinner；任务卡「真实职场任务」；三张 csv 面板（排期 / 人员 / 预算）先弹空壳，念到哪张哪张填行。
5. 青色扫描线扫过三表 → 冲突格变琥珀 `≠` → 逐个翻成绿色 `✓`，行间连线点亮，状态栏 `3 conflicts → 0`。
6. 硬切 → `eval --judge post-hoc`，左边 eval.log 逐行出，右边 400px 等宽大数字 43（琥珀）→ 滚动到 78（绿），分数条同步填充并留 43.1 刻度；推近 + `✔ +34.7` 徽章。
7. 12.6s 拉回，底部出海报条「Harness² · 权重 0 改动，分数 43 → 78」，定格。

**动效规则**：入场一律 scale-pop（0.9→1，back 缓动）+ 24px 位移、错峰 60–120ms；推近 = 0.25s 到 1.08–1.12、quint-out，保持到下一个切点；每个镜头内有 1.2%/s 的缓慢推进避免"死帧"；只在 3 个段落切点用硬切 + 2 帧 glitch（闪白 10% + 5 条彩色切片 + 横向抖 18px），其余是同一元素连续变形；静态扫描线 1.8% 叠加。光晕全部用层叠 box-shadow / text-shadow，不用 blur filter。

**固定元素**：顶部进度条做成 IDE 标签栏，8 个 tab（01–08 等宽体编号 + 中文节名），当前「01 钩子」绿色描边发光，内部有填充 + 3px 绿色进度底线 + `00:07 / 00:29` 时间码，全片进度为 bar 底部 2px 绿线；字幕为暗色半透明圆角条 + 1px 边框，前缀绿色 `›`，Harness / 43 / 78 用等宽体按语义着色；头像下加绿色地面光和发丝线作底座。

**适合**：AI / 工程 / 开发工具类论文、产品更新解读、benchmark 与数字型结论；观众是程序员、ML 从业者。
**缺点**：信息密度高、英文代码多，泛人群会觉得"冷"；画面依赖小字号等宽体，手机端次要信息（文件名、日志）偏小；风格容易滑向"黑客炫技"，需要严格控制颜色数量；长视频全程用会单调，需要在讲机制的段落换成更图解的画法。
