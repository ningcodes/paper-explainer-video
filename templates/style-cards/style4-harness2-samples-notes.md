## 怎么设计的
整段是一张 FT 粉色“版面桌”：四块版面放在同一个世界坐标里（R1 论点 → 右移 R2 案例 → 下移 R3 结果 → 剪报落桌），镜头在上面平移、推近、拉远，全程没有整屏淡出，也没有交叉溶解。设计系统直接沿用 `ref_s4_editorial.html`：色板、栏目短线 kicker、1px/4px 分层细线、宋体 Black 标题、Inter tnum 数字、麦色下三分之一字幕条、左下灰色来源行，顶部栏目导航进度条按简报的 8 节时间重算（全片 348.8s，01 钩子下划线按 t/29.5 走）。

## 和 v3.1 相比改了什么
- 开场从「大数字卡」改成报纸头版：同一组 43 / 78 先满屏出现，再缩进副标题，后面在结果图里换成 220px 的大字回来，前后呼应。
- 「模型 + Harness」不再每镜重画：同一张图贯穿三块版面，靠缩放和颜色变化讲完「原版（蓝）→ 改完后（酒红）」，同一个模型、只换外层，这件事一眼能看出来。
- 「标准答案 ✗ / 分数看不到 ✗」从两张卡升级成：卡片划掉 + 胶条直接贴在图表的分数上，「看不到」落在具体对象上。
- 论文第 1 页从截图换成实体剪报：真实坐标的荧光笔、酒红批注、带旋转的镜头推近和摇镜；Harness² 从纸上浮起来变成报头，两条预告条从原文的具体位置长出来，并和顶部导航联动。

## 「43.1 不能像是传给 Opus」怎么做
- 43.1 放在左栏（执行者那一栏）底部的**灰色虚线侧框**里，标题直接写「事后评分 · 管线看不到」，没有任何箭头连着它。
- 右栏 Opus 唯一的输入就是执行记录：唯一一根跨过中缝的箭头从 Gemini 指向记录纸，Opus 写着「只看执行记录 ↓」。
- 22.7s 分数框加一个「⊘ Opus 看不到」胶囊，正好对上口播「Opus 看不到分数」。
- 颜色也分开了：原版、基线、Gemini 用牛津蓝；改 Harness 的 Opus 用酒红；对上账用青；占位和被拒用灰。

## 事实核对（都来自 paper.pdf）
- 图 9 TASK 框：JOBBENCH · PRODUCERS / task1 / “Reconcile schedule, roster and budget files into interconnected production deliverables.” / BASE HARNESS 43.1；两个失败模式 “Figures never reconciled across files”“Outputs never reopened after writing”（第 12 页，pdftotext 核对过；剪报是 600dpi 原图裁出来的）。
- 第 12 页正文：“evaluated using Gemini 3.5 Flash and OpenCode … baseline run scored 43.1 … data was never reconciled across source files, and outputs were never reopened … restored the memo's missing sections”。所以「备忘录 MEMO」有原文依据。「制作计划」是口播词，原文是 production deliverables，卡片注「互相关联的制作交付物」。
- 第 7 页：“frozen executors under the off-the-shelf OpenCode”“default harness editor is Claude Opus 4.8 running under OpenCode”→ 对应「权重冻结」「开源，现成的」「论文默认的 Harness 编辑者 / 同样在 OpenCode 下运行」。
- 执行记录 01–06 是示意，不是论文里的轨迹；画面上盖了「示意」章，来源行也写了「执行记录为示意」。文件名一个都没编（不写 xlsx 之类的文件名）。

## 和 v3.1 比改了什么
- v3.1 是「一镜一张卡」；这里改成一张报纸跨页，镜头在版面上平移和变焦，四步导航同时出现在两处：版面里（开篇目录）和 rail（常驻在进度条下面）。
- 原文证据加强了：真纸 → 推进 → 荧光笔 → 截图浮起 → 荧光带飞出去变成任务卡下划线，元素都能看出来自哪里；结尾两个毛病旁边钉着图 9 原文剪报。
- 两模型分工从「流程链」改成报纸的双栏对照（EXECUTOR / EDITOR），分数挪到侧边的虚线框，去掉了分数 → Opus 会引起误读的那条链。
- 关键数字 43.1 在 1.25x 下约 257px，分屏 1x 下 206px，滚动出现，配 key tick。
