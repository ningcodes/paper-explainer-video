## 2. 页面接口（硬约束）

```html
<div id="stage"><div id="content"> …你的画面… </div></div>
<script src="../kit/timeline.js"></script><script src="../kit/chrome.js"></script>
<script>
CHROME.init({chapter:'04', /* 可选: */ offset:0, length:null, steps:[...], band:t=>0..1, avDim:t=>0..1});
function seek(t){ /* 你的画面，t = 本段局部秒 */ CHROME.seek(t); }
window.seek=seek; window.DURATION=CHROME.duration;
window.CUES=CHROME.cues().concat([ /* 你的音效 */ ]);
window.READY=(async()=>{ await CHROME.ready(); /* 等你的图片和字体 */ seek(0); return true; })();
</script>
```
- `seek(t)` 是 t 的纯函数：不用 CSS animation/transition、rAF、setTimeout、Date.now、Math.random（用种子 PRNG）；帧乱序渲染，不能依赖上一帧状态。不用 WebGL；全屏 CSS blur/filter 逐帧很慢，少用（运动模糊用 12–16 份等权采样，或者用 CSS 的小范围 `filter:blur()` 只作用在移动的元素上）。每帧 < 0.3s。
- `band(t)`：论文纸或任何内容会出现在 y>940 时返回 1（字幕后面加不透明麦色全宽带，别让论文正文从字幕下漏出来），否则 0。
- `avDim(t)`：镜头推近论文超过约 1.4 倍时返回 1（头像整个向下滑出画面；写成 0.35s 的平滑斜坡）。
- 音效 cue：`{t, type:'whoosh', d, soft}` / `{t,type:'pop',soft}` / `{t,type:'tick',key}` / `{t,type:'scratch',d}`（荧光笔、马克笔划线）/ `{t,type:'paper'}`（纸张浮起、翻页）。pop 对齐元素真正进场那一帧；没有画面运动的时刻不放 whoosh；数字滚动用 tick。
- **章节开头（offset=0 且不是第 01 章）**：chrome.js 自动做 0–0.6s 整页横滑翻报纸（上一章最后一帧往左退，你的页从右边推进来）。所以**你的 t=0 画面必须已经是一张完整的开场版面**（kicker + 大标题或主角元素已在位），进场动画从 t≥0.5 才开始；你的最后 0.5s 要是一个落定的版面（它会成为下一章翻页时被推走的那一页）。

## 3. 风格卡 ④ 报刊数据新闻（必须遵守）

- 色板：纸 #FFF1E5｜墨 #33302E｜次要 #66605C｜细线 #CCC1B7｜**FT 酒红 #990F3D = 改进后 / 关键数字 / 我们的标注**｜**牛津蓝 #0F5499 = 基线 / 原版**｜青 #0D7680 = 对上、连线、✓｜灰 #B9AFA6 = 被拒 / 中性｜麦色面板 #F2DFCE。颜色语义全片固定，不混用。
- 字体：中文标题 Noto Serif CJK SC Black（钩子 132px、章节标题 92px、卡片 56–64px，行距 1.1）；正文、标签 Noto Sans CJK SC；数字 Inter 800 + tnum；kicker（栏目小标签）Inter / 思源黑 Bold 28px、字距 0.14em，上压一条 56×5 酒红短线。
- 版式：头版结构 = kicker + 大标题 + 导语（dek）+ 图；左边距 120px、严格栏格；1px 细线和 4px 粗线分层；图表只画横向网格线，标签直接贴在线和点上，不用图例；注释 = 细引线 + 一句短说明；每屏左下角灰色来源行（≥26px，y≈898，「来源：Harness² 论文第 N 页图/表 X」，示意内容写「示意」）。
- 标志动作：标题逐行遮罩上推（easeOutQuart 0.55s）；导语从左擦出；细线从左长出；外框顺时针描边、描到哪个部件哪个标签出现；折线 / 柱从左画到右、旁边数字同步滚动；关键短语用酒红下划线扫出；图表镜头缓推 3–4%。**不弹跳、不发光、不用阴影卡片堆叠**。
- 论文 PDF 是白纸实体页（真页面 + 轻阴影 + 纸纹 + 约 2° 倾斜），在粉底上像一张剪报。引用原文：纸滑进来 → 镜头推进 2–3 倍到那句话 → **黄色荧光笔 rgba(250,199,117,0.7) multiply 跟口播从左往右涂**（配 scratch）→ **原文清晰停留 ≥3 秒**（不算进出场）。我们自己的标注（引线、圈、下划线、批注）用酒红。讲论文里的图时，把图里那一块「浮起」飞出来变成重画的卡；浮起的截图停在旁边，不盖住正在讲的卡，用完收进角落成「图 9 ↗」小角标。论文 logo 一律遮掉（白补丁压在纸纹下）。
- 运镜：章内用**连续变形**（下一镜的元素从上一镜里长出来，每个进场元素都有来处）、**钻进论文**、**大画布平移**（步骤从左到右排在一张跨页上，镜头 0.5–0.9s easeInOutCubic 平移 + 运动模糊 + whoosh，下一站的骨架提前露出）。**禁止**整屏淡出到空白再重搭、整屏交叉溶解（像翻 PPT）。同一个物体跨镜头用同一个 DOM 元素插值位置/缩放，不复制一个新的淡入。
- **高密度规则（频道主认可，必须做到）**：
  1. 一屏一个主角：两个角色 / 两栏不常驻；讲谁就让谁占约 65% 宽、镜头推近 1.3–1.5 倍；换主角时上一个收成顶部摘要细条；只在点明关系的那句拉远看全 1–2 秒
  2. 文字限额：字幕之外每屏 ≤ 约 25 个中文字、≤4 个视觉块；口播说过的话不再写成标签；一个元素最多一个标签
  3. 不用中英双标签（WEIGHTS / EXECUTOR 一律不要，只留中文；文件名、模型名、benchmark 名这类专名保留英文）；所有要读的字 ≥28px，来源行可 26px
  4. 看不清的论文小剪报不放：要引用就全尺寸钻进去看清 ≥1.5s
  5. 占位克制：下一栏只留一条细线 + 小栏头，不铺大片灰色骨架
  6. 顶部只有 chrome.js 那一条导航；不要在画面里再做一排步骤条
- 安全区：y<64 只给进度条（你的内容不进）；要读的内容放 x<1640、y<940；字幕区 y 958+ 不放内容（除非 band=1 且那是论文纸背景）。
- 不留空屏：内容铺满画面约 70%；任何时刻半屏空着不超过 1 秒；段落开头那一行字（「效果怎么样？」）落下时已有第一块内容。
- 画面语义别误导：竖排箭头链会被读成数据流。不流向下一个角色的东西放旁边、虚线框并标注。
- 关键数字 ≥200px；字体四级层级（标题 / 导语 / 标签 / 数字）拉开。

## 4. 事实（不许编）

所有数字、表格内容、文件名、模型名必须来自论文——**动手前用 pdftotext 在 paper.pdf 里核对你这一段用到的每一个数**，在 STYLE_NOTES.md 里列「数字 → 页码/表号」。示意性的画面（例如执行记录的具体行）标「示意」。口播里的说法就是口径，画面不能比口播说得更强（例如 43.1 → 77.8 是论文挑出来的单个案例、事后评分）。

## 5. 工作方法与预算

- CPU 只有 2 核，9 个 agent 共用。**只用 `--times` 抽帧预览，`--workers 1`，每轮 ≤10 帧**；看运动时用 6fps 抽一小段（≤18 帧）。**不要渲染整段**（主控最后统一渲染）。
- 至少 3 轮「抽帧 → Read 看图 → 修改」。每个镜头看「进场中 / 落定 / 离场前」3 帧，像海报一样能单独截图才算过。最后一轮把全段每 1.5s 一帧拼成联系表 `review_sheet.png` 自查（可以分几次渲）。
- 自查清单：文字重叠/裁切、元素压到头像或字幕、空屏、字太小（<28px）、元素凭空出现、整屏淡入淡出、荧光笔颜色用错、logo 没遮、数字和论文不符、内容进入 y<64、字幕区下漏出论文正文（band）。
- 交付（你的目录里）：`scene.html`、你渲染的素材、`review_sheet.png`、`STYLE_NOTES.md`（中文：镜头表〔时间码 · 口播 · 画面 · 运镜手法〕、数字出处表、和 v3.1 相比改了什么、剩余弱点带时间码）。完成后最后一条消息用三五行说清交付了什么、哪里还弱。
